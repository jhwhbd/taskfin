# 家庭功能增强方案（提案 · 未实现）

> 目的：把调研到的同类产品亮点，落地到 taskfin 现有架构（Vikunja + ezBookkeeping + n8n）。
> 本文档只给**方案与改动清单**，待你确认是否做、做哪些，再动手实现。
> 复用前提：项目已有 `by:<用户>` 共享账号标记、`#vk-<任务ID>` / `#recur-<标识>` 评论 token、以及 `ezbookkeeping-bill-reminder.json` / `ezbookkeeping-poll.json` 两个 n8n 流程。

---

## 功能一：家务 / 任务自动轮转（借鉴 OneHaus / Cozi）

### 目标
家庭成员之间按周期自动轮换家务负责人（如倒垃圾本周爸爸、下周孩子），无需手动改 assignee。

### 现有可复用能力
- Vikunja：多用户（部署手册 §5.4 已开多用户）、任务可设 **assignees**、支持 **labels（标签）**、支持 **重复任务（repeat_after / 到期日）**。
- 已有 `by:<用户>` 标记约定（共享账号场景），可直接用作"轮转成员"标识。

### 设计方案（推荐：n8n 驱动，不碰源码）
1. **约定**
   - 建项目 `家务`， chores 任务打标签 `chore` + `rotate`。
   - 轮转成员清单：用标签 `rot:爸爸` / `rot:妈妈` / `rot:孩子` 标注在任务上（同时保留 Vikunja 原生 assignees 作展示）。
   - 轮转顺序与周期：由 n8n 工作流按固定数组 `[爸爸,妈妈,孩子]` 循环。
2. **新增 n8n 流程 `vikunja-chore-rotate.json`**
   - 触发器：Schedule（如每周一 08:00）。
   - 步骤：
     - `GET /tasks?filter=label:chore+label:rotate`（或按项目 ID 拉取）取得所有轮转家务；
     - 对每个任务读取当前 `rot:*` 标签 → 计算下一成员；
     - `PUT /tasks/{id}` 更新 labels（移除旧 `rot:*`、加新 `rot:*`）并 `PUT /tasks/{id}/assignees` 设置 assignee；
     - 写入一条评论 `by:n8n 轮转→<下一成员>` 留痕。
3. **文档**：在 `docs/实施部署手册.md` 增 §5.8「家务轮转配置」，说明标签约定与流程导入。

### 预期效果
- 每周一自动把家务指派给下一位家庭成员，Vikunja / CalDAV / 邮件提醒同步更新。
- 改动**只新增 1 个 n8n JSON + 文档**，不动 Vikunja/ezB 源码。

### 工作量与风险
- 工作量：约 0.5–1 天（n8n 编写 + 真机联调 assignee/label API）。
- 风险：Vikunja 多用户需先建好家庭成员账号（§5.4）；轮转状态存在标签上，若手动改了标签会"错拍"——可接受。

## 功能二：一体化「家庭周视图」（借鉴 SameNest / Cozi）

### 目标
把**任务（Vikunja 到期日）+ 账单（ezB 周期交易到期）**聚合到**同一个日历**，手机/桌面订阅一个 CalDAV 即可看全家的待办与缴费。

### 现有可复用能力
- Vikunja：任务有 due date → 自带日历视图；且已配 CalDAV（部署手册 §8.1），客户端可订阅。
- ezB：周期交易（周期交易自动过账）有固定扣款日；已有 `ezbookkeeping-bill-reminder.json` 在临期发提醒。
- 已有 `#vk-<任务ID>` 评论关联机制（poll 流程用过）。

### 设计方案（推荐：账单 → Vikunja 日历任务）
1. **约定**
   - 建项目 `账单`（或复用现有财务项目），账单任务打标签 `bill`；标题形如 `💡电费 ¥120 @2026-08-25`。
2. **新增/扩展 n8n 流程 `ezbookkeeping-calendar-sync.json`**（扩展而非改 bill-reminder）
   - 触发器：Schedule（每日 06:00）。
   - 步骤：
     - `GET /ebk/api/v1/transactions?category=周期性&future=30d` 拉取未来 30 天周期交易；
     - 对每条：用评论/`#vk-` 去重（已在库则更新 due date，不在则 `POST /tasks` 建任务，due = 扣款日，project=账单，label=bill）；
     - 这样账单以「带到期日的任务」形态进入 Vikunja 日历。
3. **CalDAV 订阅**：部署手册 §8.1 已说明 Vikunja CalDAV；补一句「把 `账单` 项目订阅到手机/Google 日历，即可与任务同屏」。
4. **可选增强**：家庭事件（生日/出行）也建为 Vikunja 任务 → 真正"周视图"。

### 预期效果
- 一个 CalDAV 日历同时显示：家务待办、项目截止、账单缴费日、家庭事件。
- 改动**只新增 1 个 n8n JSON + 文档微调**，不动源码。

### 工作量与风险
- 工作量：约 0.5–1 天（复用 poll 的 ezB 读取与 Vikunja 写入模式）。
- 风险：⚠️ **B1（CalDAV 手机闹钟）**：Vikunja CalDAV 可能只同步事件、不导出 VALARM，手机未必弹提醒——账单提醒仍以 **QQ 邮件兜底**（现有机制）。日历"看得到"可靠，"弹闹钟"不一定；这点需真机验证。

## 落地前需要你确认的两点
1. **成员模型**：家务轮转 / 周视图都假设「已在 Vikunja 建好家庭成员账号（多用户）」。当前部署手册 §5.4 开了多用户但账号尚未建——是否先把家庭账号体系定下来？
2. **通知通道**：轮转结果、账单日历事件的通知，除邮件外是否要接 Telegram/微信（可走 n8n）？这会影响两个流程的"通知"节点设计。

> 以上两项均**未改动任何代码/文件**。确认后我再写对应的 n8n JSON 并补文档。
