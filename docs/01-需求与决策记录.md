# 需求与决策记录

> 按时间线记录用户从"找参考"到"方案定稿"的全部需求与拍板。供下一台 WorkBuddy 了解每个决策的来源。
> 关联文件：`03-实施部署手册.md`（落地细节）、`02-审查问题与待办.md`（未决项）。

## 一、原始需求（起点）
用户要做一个任务管理器，需支持：
- 层级：类别、项目、任务
- 字段：起止时间、里程碑、截止日期、临期提醒、到期提醒、交付物、任务详情、所需资源、所需资金
- 运行：群晖 Docker，用**邮件**发提醒
- 访问：网页端，自适应 PC + 移动端
- 第一步动作：先在 GitHub 找类似可借鉴项目，由用户判断哪个更贴合，再给下一步指令

## 二、候选对比阶段（GitHub 调研）
调研并对比 6 个开源项目：Leantime、Vikunja、Ticky、DooTask、tududi、TaskLedger。
关键结论：**没有任何开源项目原生支持「所需资源 / 所需资金 / 交付物」三字段**，都必须二次开发或用标签近似。

## 三、移动端对比
6 个项目均响应式 Web 可用；DooTask 有真原生 App；Vikunja/tududi/Leantime 走 PWA；Ticky 仅响应式。

## 四、硬件与资源核查
- 群晖 DS1618+（Atom C3538 4 核，32GB RAM），已跑 WoW 私服 Docker（约 2–4GB RAM）。
- 结论：RAM 充足；CPU 弱但轻量应用足够；最轻方案优先单容器。

## 五、财务打通需求（新增）
用户希望"资金使用层面"有类财务管理：查看支出/收入/结余、有统计分析。问能否与 Vikunja 结合。
- 调研 Firefly III（统计最强、移动端弱）与 ezBookkeeping（有原生 App、最轻、统计够用）。
- 决策：**用 Vikunja 做任务基底 + n8n 桥接 + ezBookkeeping 做财务**。

## 六、逐轮决策时间线

### 第 1 轮：选基底
- 用户选 **Vikunja** 作任务基底；财务系统**待定**（Firefly III vs ezBookkeeping 二选一）；桥接深度选 **B（n8n 自动桥接）**。
- 资金字段方案：先**Path A 标签编码**（零代码）。

### 第 2 轮：财务对比 + 给出大概方案
- 给出 Vikunja + n8n + 财务系统整体架构与 docker-compose 草案、n8n 工作流设计、Firefly vs ezBookkeeping 对比。

### 第 3 轮：定财务系统
- 用户选 **ezBookkeeping**；资金做**自定义字段**（实际落地为 Path A 标签）；Vikunja 优先 **SQLite**。
- 产出完整项目方案文档（v2.0）。

### 第 4 轮：移动端/网络细节
- 用户要求：HTTPS 证书用自签或免费（不要频繁手动替换）；至少 3 普通用户 + 1 管理员（或 3 人中 1 人兼管理员）；三系统内部通信不走外网。
- 产出 v2.2，新增用户模型、内部通信矩阵。

### 第 5 轮：网络确认
- 真公网 IP；有自有域名但**动态 IP**；QQ 授权码可获取。
- 方案定为：自有域名 + NPM + Let's Encrypt + **ddns-go**。

### 第 6 轮：域名服务商
- 域名在 **Namecheap**（BasicDNS）；主域名在用，需用**子域名**挂载本服务。
- ddns-go 原生支持 Namecheap，改成子域名方案。

### 第 7 轮：确认 BasicDNS → 出实施手册
- Namecheap BasicDNS 确认；产出《实施部署手册》v2.3 + 4 个 n8n 工作流 JSON。

### 第 8 轮：6 点补充
- A 占位符保留待定稿一次性替换；B 用户清单用占位符；C 资金池只设**现金、存款**两类；D 备份共享文件夹用**群晖 `/share/backup`**；E 预算"能看到偏差即可"无需二次开发；F **需要 CalDAV**；新增**定期扣款项（贷款还款）**。
- 产出 v2.4 / v2.5。

### 第 9 轮：4 点确认
- ① ezB 周期交易自动过账（钱真扣）、Vikunja 仅跟踪；② 提醒按任务/项目手工设定提前量、手机由 CalDAV 覆盖、**贷款不提醒**；③ 周期交易仅每月；④ 定期扣款不拆分，额度随时调。
- 产出 v2.6。

### 第 10 轮：审查 + 交接
- 用户要求：先总结检查问题/疏漏，再把整个项目形成几个文档，便于导出交给另一台机器的 WorkBuddy 继续。
- 动作：审查手册并修复 11 处一致性硬伤（v2.7），产出本交接包（`00/01/02/03` + 脚本 + n8n JSON）。

## 七、需求 → 落地映射（最终）
| 原始需求 | 落地方式 |
|---|---|
| 类别 | Vikunja Namespace |
| 项目 | Vikunja Project |
| 任务 | Vikunja Task |
| 起止时间 | Vikunja start date / end date |
| 里程碑 | `milestone` 标签任务 + 过滤器汇总 |
| 截止日期 | Vikunja due date |
| 临期/到期提醒（邮件） | Vikunja 原生 Reminder（QQ SMTP）+ CalDAV 手机提醒 |
| 交付物 | `deliv:` 标签 |
| 任务详情 | Vikunja 任务描述 |
| 所需资源 | `res:` 标签 |
| 所需资金 | `fund:` 标签（金额:币种:账户） |
| 支出/收入/结余/统计 | ezBookkeeping 内置报表 |
| 定期扣款（贷款） | ezB 周期交易（每月自动过账）+ Vikunja「定期扣款」项目跟踪 |
| 多用户 | Vikunja 3 人（1 管理员）；ezB 1 共享账号 |
| 移动端自适应 | 响应式 Web + PWA（Vikunja）；ezB 官方 App |
| 手机系统提醒 | CalDAV（Vikunja） |
| 外网访问 | NPM + Let's Encrypt + Namecheap DDNS |
| 内部联动 | n8n，走 Docker 内网 |
| 备份 | 原生全量 + 高压缩 + `/share/backup` + 留 3 份 |

## 八、明确"不做"的事（避免下一台 WB 走偏）
- 不换 Firefly III（财务选定 ezBookkeeping）。
- 不二次开发真自定义字段（用 Path A 标签）。
- 不做独立预算对象/看板（用 plan/done 标签交易近似）。
- 不开 2FA。
- 不拆"定期扣款"子项（单一入口，额度随时改）。
- 贷款不提醒（无 Vikunja Reminder、无 ezB 提醒、无 CalDAV 闹钟）。
- 备份不走邮件（写群晖共享）。
