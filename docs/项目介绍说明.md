# 项目介绍说明 · 自托管「任务 + 财务」管理系统

> 本文档用通俗语言介绍这个项目在做什么、能做什么、为什么这么设计，以及当前的状态与已知风险。
> 技术细节与可照做的部署步骤见同目录《实施部署手册》。

---

## 一、这是什么

我们想在**自己的群晖 NAS**上搭一套系统，把日常工作的**「任务管理」和「记账/财务」**合在一起管，不依赖任何第三方云服务（数据自己掌握）。

核心痛点：

- 任务分散、到期容易忘；
- 一个项目花了多少钱、还剩多少预算，没人说得清；
- 贷款 / 定期扣款这类固定支出，希望自动记账、不用每月手动记；
- 想在电脑和手机上都能用，还能在手机上收到提醒。

系统由三套开源软件组成，全部跑在群晖 Docker 内网里：

- **Vikunja** —— 任务管理（类别 → 项目 → 任务）；
- **ezBookkeeping** —— 财务管理（记账 / 统计 / 定期扣款）；
- **n8n** —— 自动化桥接，让上面两套系统双向联动。

## 二、能做什么

### 1. 任务管理（Vikunja）

| 能力 | 说明 |
|---|---|
| 三层结构 | 类别 → 项目 → 任务，层级清晰 |
| 时间管理 | 每件事可设**开始时间 / 结束时间 / 截止日期** |
| 里程碑 | 用「里程碑」标记关键节点 |
| 提醒 | **临期提醒 + 到期提醒**，通过邮件发送；提前几天可每个任务单独设 |
| 交付物 | 记录这件事要交付什么（文件/文档） |
| 任务详情 | 描述、负责人、优先级等 |
| 所需资源 | 记录这事需要什么资源（人/物/设备），用标签记 |
| 所需资金 | 记录这事预算多少，用标签记（如 `fund:5000`） |
| 移动端 | 手机浏览器加到主屏当 App 用；还能通过 **CalDAV** 把任务同步进手机系统提醒 |

### 2. 财务管理（ezBookkeeping）

| 能力 | 说明 |
|---|---|
| 记账 | 支出 / 收入 / 结余一目了然 |
| 统计分析 | 收支趋势、分类占比、净资产曲线等图表 |
| 资金池 | 只分「**现金**」「**存款**」两大类 |
| 多用户共享 | 一个共享资金池，谁记的账都带 `by:用户名` 标记，可追溯 |
| 移动端 | 有官方手机 App（安卓/iOS），登录即用 |
| 定期扣款 | **贷款还款**这类每月固定支出，设为「周期交易」后**自动记账**，不用手动 |

### 3. 两套系统自动联动（n8n 自动化）

- 在任务里填了预算 → 在 Vikunja 任务下留一条「预算」评论（仅计划，不写 ezB 真实支出，避免双重记账）；
- 任务标记完成 → 财务侧自动记一笔「实际支出」；
- 财务侧贷款自动扣款 → 自动把对应的任务勾掉，不重复记。
- 三套程序都跑在同一台 NAS 内网里，互相通信不经过外网，更快也更安全。

### 4. 访问与部署

- 跑在群晖 Docker 里，外网用 **HTTPS（加密访问）** + 自有域名访问；
- 电脑/手机浏览器自适应，手机也能顺畅操作；
- 数据每天自动备份，只保留最近 3 份，存在 NAS 共享文件夹里。

## 三、整体架构

```
   电脑 / 手机  ──HTTPS──▶  Nginx 反代  ──▶  tasks.你的域名  → Vikunja（任务）
                                      ├──▶  fin.你的域名   → ezBookkeeping（财务）
                                      └──▶  flow.你的域名  → n8n（自动化后台）

   Vikunja ──Webhook──▶ n8n ──API──▶ ezBookkeeping   （任务→财务 自动同步）
   ezBookkeeping ──轮询──▶ n8n ──API──▶ Vikunja       （财务→任务 自动同步）
   全部走 NAS 内网，不经公网
```

技术栈：Vikunja + ezBookkeeping + n8n + Nginx Proxy Manager + ddns-go，均为 Docker 容器，数据库用轻量的 SQLite。

---

## 四、关键设计决策

- 任务系统用 **Vikunja**，财务系统用 **ezBookkeeping**（不选用 Firefly III，因其无手机原生 App）；
- 自动化用 **n8n** 双向同步；
- 任务里的「所需资源 / 所需资金 / 交付物」用**标签**记录（零代码，先跑通，不做二次开发自定义字段）；
- 用户：任务系统 3 个账号（其中 1 人兼管理员），财务用 1 个共享账号；
- 不开启两步验证（2FA）；
- 定期扣款（如房贷）由财务系统**每月自动过账**，任务系统只做跟踪、不弹提醒；
- 预算不做独立预算对象/看板：预算只在 Vikunja 任务下留「预算」评论（不写 ezB 真实交易），实际支出由 n8n 在 ezB 记一笔 type=3，靠两端 `#vk-<任务ID>` 关联对比偏差；
- 备份写 NAS 共享文件夹，仅留 3 份，不走邮件。

## 五、需求 → 落地映射

| 原始需求 | 落地方式 |
|---|---|
| 类别 | Vikunja Namespace |
| 项目 | Vikunja Project |
| 任务 | Vikunja Task |
| 起止时间 | Vikunja start date / end date |
| 里程碑 | `milestone` 标签任务 + 过滤器汇总 |
| 截止日期 | Vikunja due date |
| 临期/到期提醒（邮件） | Vikunja 原生 Reminder（QQ SMTP）+ CalDAV 手机提醒 |
| 交付物 | `deliv:` 标签 |
| 任务详情 | Vikunja 任务描述 |
| 所需资源 | `res:` 标签 |
| 所需资金 | `fund:` 标签（金额:币种:账户） |
| 支出/收入/结余/统计 | ezBookkeeping 内置报表 |
| 定期扣款（贷款） | ezB 周期交易（每月自动过账）+ Vikunja「定期扣款」项目跟踪 |
| 多用户 | Vikunja 3 人（1 管理员）；ezB 1 共享账号 |
| 移动端自适应 | 响应式 Web + PWA（Vikunja）；ezB 官方 App |
| 手机系统提醒 | CalDAV（Vikunja） |
| 外网访问 | NPM + Let's Encrypt + Namecheap DDNS |
| 内部联动 | n8n，走 Docker 内网 |
| 备份 | 原生全量 + 高压缩 + 群晖共享 + 留 3 份 |

标签编码约定（任务侧）：

- `res:xxx` —— 所需资源；
- `fund:金额:币种:账户` —— 所需资金（账户为 `cash` 现金 / `deposit` 存款，默认现金）；
- `deliv:xxx` —— 交付物；
- `milestone` —— 里程碑节点；
- `recur-<标识>` —— 定期扣款任务的月度实例匹配标识。

## 六、明确不做的事（避免范围蔓延）

- 不换 Firefly III（财务已选定 ezBookkeeping）；
- 不二次开发真自定义字段（用标签近似）；
- 不做独立预算对象/看板（用 plan/done 标签交易近似）；
- 不开 2FA；
- 不拆「定期扣款」子项（单一入口，额度随时改）；
- 贷款不提醒（无 Vikunja Reminder、无 ezB 提醒、无 CalDAV 闹钟）；
- 备份不走邮件（写群晖共享）。

## 七、当前状态与已知风险

**当前状态**：方案已定稿，配置（`docker-compose.yml`、`.env.example`、n8n 工作流 JSON、备份脚本）与文档齐备，处于**待真机部署联调**阶段。所有配置均对照 vendor 源码逐键核查，文档与配置文件保持一致。

**部署前重点验证的已知风险**（完整逐条处理指引见《实施部署手册》§12）：

- **B1（最高风险）CalDAV 手机闹钟可靠性**：Vikunja 的 CalDAV 可能只同步任务/到期日、不导出 VALARM 闹钟，手机系统提醒可能落空，需实机验证；不行则以 Vikunja 邮件提醒兜底。
- **B2（高风险）n8n 五个工作流 JSON 未实机联调**：导入后必须用手动执行 + 真实 token 逐步跑通，再启用 Webhook / 定时；节点 `typeVersion` 需与所装 n8n 版本匹配。
- **B5（中风险）ezB 周期交易「每月」的准确字段表达**：需在 ezB Web 建周期交易时确认参数。
- **B6（中风险）Vikunja 重复任务完成语义**：`ezbookkeeping-poll` 按 `recur` + `#recur-<标识>` 标签匹配 recur 任务并 `POST /tasks/{id}` 置 `done=true`。但 Vikunja 重复任务（带 `repeat_after`）**不生成新实例**、被标记完成后会原生**重置为未完成**并顺延到期日（源码 `setTaskDates*` 均把 `Done` 置回 `false`）——故完成仅以 `done_at` 时间戳 + 回写评论持久记录，视觉上不常驻"已勾选"。实机需确认：① `done_at` 与评论落库；② 到期日自动顺延；③ 任务回到待办。因同一任务 id 长期保留标签，poll 跨月稳定命中同一任务，闭环持续有效。若必须视觉常驻"本月已勾掉"，需改用非重复任务或另设专用跟踪任务。
- 另有 B3（备份共享真实挂载路径）、B4（DSM 上 7z 二进制名）、B7（n8n 内部 URL 与服务名）为部署细节风险。

**待拍板的开放项**（见《实施部署手册》§13）：占位符一次性替换（真实域名 / 邮箱 / 项目目录 / 用户清单 / n8n 变量真实值）、备份共享是否已建、统计呈现细节、提醒提前量默认值、是否要子任务、历史数据迁移、监控告警等——多数非阻塞，可在部署时或部署后逐步确定。
