# WorkBuddy 导入指南 · 项目交接包

> 本指南给**接收本项目的新机器 / 新 WorkBuddy** 看：如何把这份交接包接手起来，继续推进「任务 + 财务自托管系统」的部署。

---

## 一、交接包里有什么

```
项目交接包/
├─ 00-交接总览.md          ← 入口，先读这个
├─ 01-需求与决策记录.md     ← 从需求到定稿的全过程决策
├─ 02-审查问题与待办.md     ← 已修复 / 待实机验证 / 待拍板，分优先级
├─ 03-实施部署手册.md       ← 可执行部署手册（v2.7，IP 已占位符化）
├─ 04-项目说明（面向使用者）.md  ← 给最终使用者的项目介绍 + 需求收集模板
├─ 05-WorkBuddy导入指南.md  ← 本文件
├─ scripts/
│   └─ backup.sh            ← 群晖任务计划用的备份脚本
└─ n8n/
    ├─ vikunja-task-sync.json      ← 任务完成→财务记账→回写
    ├─ ezbookkeeping-poll.json     ← 财务→任务（轮询回贴）
    ├─ vikunja-budget-plan.json    ← 任务新建→登预算项
    ├─ ezbookkeeping-bill-reminder.json ← 账单临期提醒（模板）
    ├─ backup-csv-7z-email.json    ← 已弃用占位，勿用
    └─ Dockerfile                  ← n8n 自定义镜像（备用，当前 compose 用官方镜像）
```

---

## 二、导入步骤（3 步）

### 步骤 1：把包拷到新机器
- 将整个 `项目交接包/` 文件夹复制到目标机器的某个工作目录（如 `D:\AI\项目交接包\` 或 `/home/user/项目交接包/`）。
- 在 WorkBuddy 里把**该文件夹作为工作区打开**（或在该目录下启动 WorkBuddy 会话）。

### 步骤 2：让 WorkBuddy 读入口文档
在 WorkBuddy 对话框里直接说：

> 请阅读工作区里的 `项目交接包/00-交接总览.md`，这是「群晖 Docker 任务+财务自托管系统」的项目交接包入口。先了解项目背景、当前进度、关键决策和待办，然后等我下一步指令。

WorkBuddy 会按顺序读 `00 → 01 → 02 → 03`，并掌握项目的全貌与风险点。

### 步骤 3：按待办推进（重点看 `02-审查问题与待办.md`）
- **A 类（已修复）**：无需再处理，了解即可。
- **B 类（须实机验证）**：部署到真机后逐项联调，尤其是：
  1. 🔴 CalDAV 闹钟可靠性（可能只同步日历事件、不弹手机闹钟，可靠提醒仍是邮件兜底）；
  2. 🔴 n8n 4 个 JSON 工作流未实机校验（标签解析 / 金额×100 / 节点 typeVersion 可能需微调）；
  3. 🟡 `/share/backup` 真实挂载路径（群晖 DSM 多为 `/volume1/share/backup`）；
  4. 🟡 群晖 DSM 上 7z 二进制名、ezBookkeeping「每月」周期参数、Vikunja recurring 新实例标签继承、n8n 内网 DNS。
- **C 类（待拍板）**：与原用户/需求方确认后再落地。

## 三、占位符替换清单（部署前必须做）

所有 `<...>` 与 IP 类占位符，需在**实机环境**替换为真实值：

### IP 类（已统一占位）
| 占位符 | 含义 | 你的环境填什么 |
|---|---|---|
| `<群晖内网IP>` | 群晖局域网 IP | 如 `192.168.x.x` |
| `<路由器IP>` | 路由器 LAN 口 IP | 如 `192.168.x.1` |
| `<光猫IP>` | 光猫管理 IP | 如 `192.168.0.1` |
| `<局域网网段>` | 局域网网段 | 如 `192.168.x.0/24` |
| `<群晖内网IP>.x` | 通配示例 | 直接替换为你的网段格式即可 |

### 非 IP 类（保留原样 `<...>`）
- `yourdomain.com` → 你的真实域名（tasks/fin/flow 三个子域名）
- `<你的QQ邮箱>@qq.com` + QQ 邮箱「授权码」（非登录密码）
- docker 项目目录（如 `/volume1/docker/taskfin`）
- Vikunja 3 用户清单（用户名/邮箱/昵称，谁兼管理员）
- ezBookkeeping 共享账号凭据 + `by:用户名` 用哪套名字
- n8n 变量（`vikunja_token` / `ezb_token` / `ezb_account_cash_id` / `ezb_account_deposit_id` 等）

> 替换时机：原用户要求「方案完全确定后一次性替换」。若你在新机器上要直接部署，可让 WorkBuddy 用「查找替换」批量处理，但务必先核对每个占位符的真实值。

## 四、给新 WorkBuddy 的推荐开场提示词

```
我是接手这个项目的新机器。请基于工作区 项目交接包/ 下的文档继续：
1. 先读 00-交接总览.md、01-需求与决策记录.md、02-审查问题与待办.md，给我一份「当前状态 + 最高风险」的 5 行摘要；
2. 帮我把 03-实施部署手册.md 里的所有 <...> 和 IP 占位符列成一张替换表（不要改文件，只列）；
3. 等我提供真实域名 / 邮箱 / 群晖目录后，再生成可直接 docker compose up 的终稿。
```

## 五、注意事项
- 这是**设计阶段完成、尚未实机部署**的资料。所有结论基于文档调研，n8n 工作流 JSON 与部分参数需真机联调。
- 安全红线（详见 03 §1）：公网只放行 80/443，三应用只在 Docker 内网，勿把群晖 DMZ 暴露全端口。
- 备份脚本 `scripts/backup.sh` 需在群晖「任务计划」里挂 cron 运行，并确认 `/share/backup` 共享已建。

*本指南随交接包 v2.7 一起提供。*
